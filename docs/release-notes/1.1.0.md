CSF 1.1.0 adds game mode for two games that play their sound on JAudio: The Legend of Zelda: Twilight Princess HD (USA) and The Legend of Zelda: The Wind Waker HD (USA). `csfrip` now finds the group files that a game keeps in SARC archives beside its sound archive. It also leaves out the files that macOS adds beside a game's files on some drives. A rip's file names now keep characters outside ASCII.

CSF rips Nintendo Wii U sequenced music into a PSF-family format. It plays the music with the game's sound code or a model of that code, along with a model of the console's mixing. The release includes a ripper (`csfrip`), a renderer (`csfplay`) and a foobar2000 component. `docs/csf.md` describes the format.

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. For macOS, see the README for instructions on building from source.

## New in 1.1.0

- **JAudio games in game mode.** Some of Nintendo's games play their sound on JAudio instead of NintendoWare's sound library. `csfrip` rips two of them in game mode: The Legend of Zelda: Twilight Princess HD (USA), on JAudio2, and The Legend of Zelda: The Wind Waker HD (USA), on JAudio1. Such a game is ripped as a whole. One `.csflib` holds the game's executable and its sound files. Each `.minicsf` plays one sound of the game's sound table. JAudio mixes the game's sound on the CPU, and the player runs that code too. `--list` lists a game's sounds, and `--only` and `--bgm` choose among them.
- **Version 2 of the format.** A JAudio game's rip names its driver in version 2 of the process descriptor. CSF 1.0.0 and 1.0.1 can't play these rips. Rips of NintendoWare games keep version 1. Older versions of CSF still play them.
- **Group files in SARC archives.** Some games keep group files in SARC archives (`.sarc`) beside the sound archive, under other names. While a group is still missing, `csfrip` now searches the SARC archives in the sound archive's folder. It adds each group file in them whose files match the sound archive's. Sequences whose banks or waves are in such a group file used to be skipped. A compressed SARC (`.szs`) isn't searched.

## Fixed in 1.1.0

- **Files that macOS adds.** macOS writes a file named "._" and the file's name beside each file that it copies to a FAT or exFAT drive. `csfrip` took such files in an extracted title for the game's files. The "._" file of a sound archive counted as a second sound archive. `csfrip` ripped the real archives, then reported an error for that file and exited with an error code. `--list` listed it too. `csfrip` now leaves out every file whose name starts with "._" when it reads an extracted title or a folder of titles.
- **Names outside ASCII.** A rip's file names keep characters outside ASCII, such as "é". Each byte of such a character used to become "_". Bytes that aren't valid UTF-8, and invisible control characters, still become "_".

Rips made with 1.0.0 and 1.0.1 play the same in 1.1.0. Rip a game again to get the sequences whose group files are in SARC archives, or to keep characters outside ASCII in the file names.

## Other changes

These change only what happens with damaged or unusual files.

- `csfrip` now recognises a GameCube or Wii disc image in a GCZ, CISO or WDF container. It says that the file is a Wii or GameCube disc image, not a Wii U game.
- A damaged PSF file whose program is cut short gets the message "truncated program data" in a case that gave "corrupt program data": when the data inflated so far ends exactly on a 1 MiB boundary.
- A float of 2^31 or more converts to the largest 32-bit integer. The Wii U's CPU converts it that way. On x86, CSF gave the smallest. Only a pitch ratio of 32,768 or more, or a mix value of 2^31 or more, reaches it.

## Building from source

CSF now shares code with other players of PSF-family formats through two libraries, xsflib and ntdlib. Each is a Git submodule. Clone CSF with `git clone --recursive`. In a clone made without it, run `git submodule update --init --recursive` before you build.

## Features

- **Ripping.** `csfrip` rips a Wii U game or a sound archive (`.bfsar`) into a `.csflib` and a `.minicsf` for each sequence. A game can be a Wii U archive (`.wua`) or an extracted title. `csfrip` requires the game's files to be stored decrypted, and both forms store them that way. Cemu's Title Manager converts disc images (WUD and WUX) and installable titles to `.wua` files. `csfrip` finds the group files that a game keeps outside its sound archive. It also looks for them in SARC archives. The ripper plays each sound to work out its length and fade tags, and skips the sequences that make no sound. `--bgm` rips only the music. `csfrip` also supports drag and drop.
- **Two rip modes.** Game mode runs the game's sound code on an emulated Espresso CPU. The rips play as they do in the game. Game mode requires a driver profile for the game. Three games have one: Animal Crossing: amiibo Festival (USA), on NintendoWare's sound library, The Legend of Zelda: Twilight Princess HD (USA), on JAudio2, and The Legend of Zelda: The Wind Waker HD (USA), on JAudio1. Archive mode plays a sound archive from any game with CSF's model of the SDK's sound library. The model follows the version of the library in amiibo Festival.
- **The console's mixing.** The Wii U mixes its voices on a DSP. The DSP's program comes with the system rather than the game. The system's sound library then mixes the result for each output. In both modes, CSF does both stages in code: the voices' resampling, filters, envelopes and volumes, and the final mix stage with its upsampling to 48 kHz. The code does the same arithmetic as the DSP's program. A JAudio game mixes its voices on the CPU instead, and the player runs the game's mixer before the final mix stage.
- **Rendering.** `csfplay` renders rips to WAV or FLAC at the Wii U's 48,000 Hz.
- **foobar2000.** The component plays `.minicsf` files using their length and fade tags. Tag editing, ReplayGain and endless playback are supported. A separate thread renders ahead of playback and keeps up to ten minutes of audio. That makes seeking within a track quick.

## Known limitations

- Game mode has profiles for three games. Other games with NintendoWare's sound library rip in archive mode. Archive mode's model follows amiibo Festival's version of the sound library. A game with another version may play differently from the console. A JAudio game without a profile can't be ripped.
- The DSP's program reads the coefficients of its resampling filters from the DSP's ROM. No file holds that ROM. CSF uses the Wii's coefficients. They're very likely the same.
- A game's code can set up the effects of the console's sound library (reverb, chorus and delay). CSF doesn't play them.
- The output is the TV's stereo mix. The GamePad's output, the Wii Remotes' speakers and surround aren't played.
- A sequence that depends on values the game sets plays as it does before the game sets any. A sequence that draws random numbers takes the same path every time.
- Sounds that play until the game stops them (such as ambiences) get two loops and a fade if the ripper can detect their loops. Otherwise, they play until their notes end. The limit is ten minutes.
- Only sequences are ripped. Use tools such as vgmstream for BFSTM streams. Wave sounds aren't ripped. Sequences whose data is in a group file that can't be found are skipped. The Wind Waker HD plays some of its music from streams. Its rip holds the music that it plays as sequences, without the game's sound effects.
- A JAudio game's rip runs the game's mixer on the emulated CPU. It renders far more slowly than other rips. A slow computer may not play it in real time.
- A seek back past the audio the component keeps renders from the start of the track. Such seeks happen only in tracks longer than ten minutes and in endless playback.
- Encrypted games (disc images and installable titles) aren't read.
