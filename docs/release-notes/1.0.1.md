CSF 1.0.1 fixes the lengths of some sounds, notes whose velocity goes past 127, and numbers in tags under some locales. `csfrip` now refuses the Switch's sound archives. It used to rip them wrongly. `csfrip` also keeps apart the rips that go in one folder. `csfplay` now refuses a WAV file that's too long before it renders anything.

CSF rips Nintendo Wii U sequenced music into a PSF-family format. It plays the music with the game's sound code or a model of that code, along with a model of the console's mixing. The release includes a ripper (`csfrip`), a renderer (`csfplay`) and a foobar2000 component. `docs/csf.md` describes the format.

## Fixed in 1.0.1

- **Lengths of sounds with several tracks.** `csfrip` could give some sounds the wrong length. A sound ran to the ten-minute limit when a track that plays no notes changed a setting in a loop before the track that plays. A sound could also run to the ten-minute limit when the track that plays counted time in a loop inside its loop. A sound could stop early when a tied note ended between two passes of its track. A sound whose last note ends by itself could get a loop and a fade.
- **Endless sounds that hold a note.** In some ambiences and machine sounds, one track loops while another holds a note that only the game stops. `csfrip` gave them the ten-minute limit. They now get two loops and a fade. So does a sound whose track holds such a note and only changes its volume or pitch in its loop.
- **Endless loops inside a subroutine.** A sound whose endless loop lies in a subroutine, and plays notes that end, ran to the ten-minute limit. It now gets two loops and a fade.
- **Notes with a velocity above 127.** A track can scale its notes' velocities past 127. Such a note played nothing on an instrument whose velocity table has a single region. It now plays that region, as on the console.
- **Switch sound archives.** A Switch game's sound archive is a `.bfsar` file too. The Switch's archives store their numbers in the other byte order. `csfrip` ripped such an archive as a Wii U one, and the sequences came out broken. `csfrip` now refuses a Switch archive and says why.
- **Numbers in tags.** CSF reads the `length`, `fade` and `volume` tags the same way under every locale. A host program could set a locale that uses a comma for decimals. Every rip then played at the default length, and a volume of 0.5 was read as 0. A comma before decimals now works in the `volume` tag too. It already worked in `length` and `fade`.
- **Long WAV files.** `csfplay` now checks the length before it renders anything. A WAV file can't hold more than a little over 6 hours. `csfplay` used to refuse a longer one only after rendering. FLAC files have no such limit.
- **Rips that share a folder.** When several inputs rip into one folder, `csfrip` gives the later rips' files other names. A later rip used to replace an earlier rip's files of the same names. That happened with `-o` and two releases of one game, or two games whose sound archives have the same name. On Windows and macOS it also happened to two inputs whose names differ only in case, such as `Game.wua` and a folder named `game`.

Rips made with 1.0.0 keep their length tags. Rip a game again to get the new lengths. Some sounds that end also get 3 ms more of silence after their last sound. The fixes for velocities past 127 and for numbers in tags work with existing rips.

## Features

- **Ripping.** `csfrip` rips a Wii U game or a sound archive (`.bfsar`) into a `.csflib` and a `.minicsf` for each sequence. A game can be a Wii U archive (`.wua`) or an extracted title. `csfrip` requires the game's files to be stored decrypted, and both forms store them that way. Cemu's Title Manager converts disc images (WUD and WUX) and installable titles to `.wua` files. `csfrip` finds the group files that a game keeps outside its sound archive. The ripper plays each sound to work out its length and fade tags, and skips the sequences that make no sound. `--bgm` rips only the music. `csfrip` also supports drag and drop.
- **Two rip modes.** Game mode runs the game's sound code on an emulated Espresso CPU. The rips play as they do in the game. Game mode requires a driver profile for the game. Animal Crossing: amiibo Festival (USA) has one. Archive mode plays a sound archive from any game with CSF's model of the SDK's sound library. The model follows the version of the library in amiibo Festival.
- **The console's mixing.** The Wii U mixes its voices on a DSP. The DSP's program comes with the system rather than the game. The system's sound library then mixes the result for each output. In both modes, CSF does both stages in code: the voices' resampling, filters, envelopes and volumes, and the final mix stage with its upsampling to 48 kHz. The code does the same arithmetic as the DSP's program.
- **Rendering.** `csfplay` renders rips to WAV or FLAC at the Wii U's 48,000 Hz.
- **foobar2000.** The component plays `.minicsf` files using their length and fade tags. Tag editing, ReplayGain and endless playback are supported. A separate thread renders ahead of playback and keeps up to ten minutes of audio. That makes seeking within a track quick.

## Known limitations

- Game mode only has a profile for Animal Crossing: amiibo Festival (USA). Other games rip in archive mode. Archive mode's model follows amiibo Festival's version of the sound library. A game with another version may play differently from the console.
- The DSP's program reads the coefficients of its resampling filters from the DSP's ROM. No file holds that ROM. CSF uses the Wii's coefficients. They're very likely the same.
- A game's code sets up effects (reverb, chorus and delay). CSF doesn't play them.
- The output is the TV's stereo mix. The GamePad's output, the Wii Remotes' speakers and surround aren't played.
- A sequence that depends on values the game sets plays as it does before the game sets any. A sequence that draws random numbers takes the same path every time.
- Sounds that play until the game stops them (such as ambiences) get two loops and a fade if the ripper can detect their loops. Otherwise, they play until their notes end. The limit is ten minutes.
- Only sequences are ripped. Use tools such as vgmstream for BFSTM streams. Wave sounds aren't ripped. Sequences whose data is in a group file that can't be found are skipped.
- A seek back past the audio the component keeps renders from the start of the track. Such seeks happen only in tracks longer than ten minutes and in endless playback.
- Encrypted games (disc images and installable titles) aren't read.
