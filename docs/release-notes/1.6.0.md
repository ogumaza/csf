In CSF 1.6.0, rips hold the variants of sounds that wait for a value from the game, and the states in which games play some pieces of music. Mario Party 10 gets a driver profile. The format moves to version 3, and CSF 1.5.0 and earlier players refuse some of the new rips.

CSF rips Nintendo Wii U sequenced music into a PSF-family format. It plays the music with the game's sound code or a model of that code, along with a model of the console's mixing. The release includes a ripper (`csfrip`), a renderer (`csfplay`), a foobar2000 component and an XMPlay plugin. `docs/csf.md` describes the format.

## New in 1.6.0

- **Effects that wait for the game's variables.** Some sound effects of games on NintendoWare's sound library read a variable that the game sets when it starts them, such as the speed of a lift or the surface under a footstep. Without the value, such an effect played nothing, and `csfrip` skipped it. Six games now have a variable profile: Animal Crossing: amiibo Festival, Mario Party 10, Nintendo Land, Super Mario 3D World, New Super Mario Bros. U (all USA) and Wii Party U (USA, Rev 1). A rip of one of them holds a variant of each such effect for each set of values in the profile, such as `SQ_SE_MG0206_JUMP 15=1`. Where a reading of the game's code found the values, the profile holds them. Otherwise it holds values from the tests that the sequence makes of the variable. Wii Party U's `SEQ_BGM_NPG006_THEMA` is music of this kind. Its variants add a layer at each level of the player's score, and the last one plays the ending. Game-mode rips of amiibo Festival hold the variants too.
- **Variables in `csf_var`.** The `csf_var` tag now also sets the variables of a sequence on NintendoWare's sound library: 0 to 15 for the sequence's variables and 16 to 31 for the global ones. `T:N=V` sets variable N, 32 to 47, of track T. The players set the variables after the sound starts and before its first tick, as a game does. In game mode, the player writes them through the game's code.
- **Track volumes.** A game's code can set the volume of each track of a sequence as it starts the sound. Kirby and the Rainbow Curse's stage select plays one piece, `BGM_SEQ_MENU_INTERACTIVE`, with one to three of its tracks. The game picks them by the view: the area view, a world's list of stages, or a world's boss stage. A rip now holds a file for each of the 15 states, such as `BGM_SEQ_MENU_INTERACTIVE world 3 boss`. The piece played every track at once before. Each state's `.minicsf` holds an archive descriptor with the state's track volumes. `docs/csf.md` describes it under "Track volumes".
- **Mario Party 10's driver profile.** Game mode can now run Mario Party 10's sound code. Game mode plays no effects, and most of the game's sequences send to its reverb. Its rips therefore take archive mode unless `--mode game` asks for game mode. Archive-mode rips of the game take its 78 voices.
- **More effect profiles.** Archive mode now plays Wii Party U's reverb on the TV's aux A. It also plays Nintendo Land's reverb in each attraction and the plaza's delay. Nintendo Land defines that reverb and that delay in its code, and archive mode plays models of the two.
- **The Wind Waker HD's music.** Game mode now starts the game's music through the game's starters, as the game does. The sound layer mutes some tracks of 14 pieces as it starts them. The game's state picks the tracks, such as the boat's sail or an enemy near Link. A rip starts each piece in the state that the sound layer starts in, with the sail down, Link off the boat, his sword sheathed and no enemy near. It also holds each other arrangement, such as `JA_BGM_SEA_SAILING` or `JA_BGM_KAMI_TOWER_80000125`. While some pieces play, the game writes a status to their port 9, such as the phase of a boss fight. A rip holds such a piece once more for each value that changes what it plays, such as `JA_BGM_P_GANON_1 9=2`. The battle music also comes with 1 on port 11, as when Link hits an enemy. Values 16 to 19 of `csf_var` set the game's state.
- **The Wind Waker HD's Stalfos.** Five of the game's effects read port 9, the reverb of the room. A rip now holds six variants of a Stalfos's step (`JA_SE_ST_WALK`), one for each reverb of the rooms that place a Stalfos, such as `9=40`. The other four make no sound with any value, and `csfrip` still skips them.
- **The Wind Waker HD (Japan).** The game's Japanese release has a driver profile too. Its rips hold the same sounds as the USA release's.
- **Twilight Princess HD's music.** As Twilight Princess HD starts five pieces, it mutes some of their tracks. A rip now mutes the same tracks. Hyrule Field's day music holds two arrangements: `Z2BGM_FIELD_LINK_DAY` plays while Link walks, and `Z2BGM_FIELD_LINK_DAY_riding` while he rides. The game's scenes and battles set the tracks of 17 pieces later, some of them to volumes between 0 and 1. A rip holds a variant of each such state after its piece, such as `Z2BGM_TOAL_VILLEGE_status1`. Hyrule Field's day music also follows the field's code: what Link does, the enemies near him and the time of day. A rip holds each way through the piece, in each arrangement.
- **Smaller JAudio libraries.** A JAudio game's `.csflib` now holds zeros in place of the wave files that the game read in none of the ripper's plays of the ripped sounds. Each file keeps its size. The game reads its wave files only before a sound starts, so a rip plays as before. A rip made with `--no-length` keeps every file whole.
- **Lengths.** The Wind Waker HD's pieces whose port variants ran to the 10-minute limit now end with two loops and a fade. A sequence whose counted loops run past the limit now loops for ever in its outermost counted loop, and gets two loops and a fade.
- **Speed.** The emulated Espresso CPU runs faster. JAudio games' rips, which run the game's mixer on that CPU, render faster as a result. The output is the same.
- **Playback.** The foobar2000 component and the XMPlay plugin now buffer 3 s of audio after the start and after each seek before playback starts. A rip that renders faster than real time on average then plays through its slow passages without gaps.
- **Compatibility.** The format is now version 3. CSF 1.5.0 and earlier players refuse the new game-mode rips of amiibo Festival, Mario Party 10, The Wind Waker HD and Twilight Princess HD, and the states of Kirby and the Rainbow Curse's stage select, with a message. Earlier players ignore the variables in `csf_var`, and a variant then plays as the effect did before. Rips made with earlier versions play as before.
- **The libraries.** CSF now builds on xsflib 1.8.0 and ntdlib 3.2.0.

## Features

- **Ripping.** `csfrip` rips a Wii U game or a sound archive (`.bfsar`) into a `.csflib` and a `.minicsf` for each sequence. A game can be a Wii U archive (`.wua`) or an extracted title. `csfrip` requires the game's files to be stored decrypted, and both forms store them that way. Cemu's Title Manager converts disc images (WUD and WUX) and installable titles to `.wua` files. `csfrip` finds the group files that a game keeps outside its sound archive. It also looks for them in SARC archives. The ripper plays each sound to work out its length and fade tags, and skips the sounds that make no sound. A rip of The Wind Waker HD holds the game's sound effects too. An effect that reads a value from the game gets a variant for each value. A piece of music that the game plays in several states gets a file for each state. `--bgm` rips only the music. `csfrip` also supports drag and drop.
- **Two rip modes.** Game mode runs the game's sound code on an emulated Espresso CPU. The rips play as they do in the game. Game mode requires a driver profile for the game. Four games have one: Animal Crossing: amiibo Festival (USA) and Mario Party 10 (USA), on NintendoWare's sound library, The Legend of Zelda: Twilight Princess HD (USA), on JAudio2, and The Legend of Zelda: The Wind Waker HD (USA and Japan), on JAudio1. Mario Party 10's rips take archive mode unless `--mode game` asks for game mode. Archive mode plays a sound archive from any game with CSF's model of the SDK's sound library. The model follows the version of the library in amiibo Festival.
- **The console's mixing.** The Wii U mixes its voices on a DSP. The DSP's program comes with the system rather than the game. The system's sound library then mixes the result for each output. In both modes, CSF does both stages in code: the voices' resampling, filters, envelopes and volumes, and the final mix stage with its upsampling to 48 kHz. The code does the same arithmetic as the DSP's program. A JAudio game mixes its voices on the CPU instead, and the player runs the game's mixer before the final mix stage.
- **Effects.** Archive mode plays the reverb, chorus and delay that a game sets up, for a game with an effect profile. Four games have one: Animal Crossing: amiibo Festival, Mario Party 10, Nintendo Land (all USA) and Wii Party U (USA, Rev 1).
- **Rendering.** `csfplay` renders rips to WAV or FLAC at the Wii U's 48,000 Hz.
- **foobar2000.** The component plays `.minicsf` files using their length and fade tags. Tag editing, ReplayGain and endless playback are supported. A separate thread renders ahead of playback and keeps up to ten minutes of audio. That makes seeking within a track quick.
- **XMPlay.** The plugin plays `.minicsf` files using their length and fade tags. Endless playback is supported. Like the component, the plugin renders ahead of playback and keeps up to ten minutes of audio.

## Known limitations

- Game mode has profiles for four games. Other games with NintendoWare's sound library rip in archive mode. Archive mode's model follows amiibo Festival's version of the sound library. A game with another version may play differently from the console. A JAudio game without a profile can't be ripped.
- The DSP's program reads the coefficients of its resampling filters from the DSP's ROM. No file holds that ROM. CSF uses the Wii's coefficients. They're very likely the same.
- A game's code can set up the effects of the console's sound library (reverb, chorus and delay). Archive mode plays them only for a game with an effect profile. Four games have one. Game mode plays without effects.
- The output is the TV's stereo mix. The GamePad's output, the Wii Remotes' speakers and surround aren't played.
- A sound that depends on values the game sets plays as it does before the game sets any, unless a profile gives it variants. A variant plays its state from the start. The game moves a piece of music into a new state over up to a few seconds. Twilight Princess HD's fights write some statuses once the piece plays. A rip leaves those states out. A sequence that draws random numbers takes the same path every time.
- Sounds that play until the game stops them (such as ambiences) get two loops and a fade if the ripper can detect their loops. Otherwise, they play until their notes end. The limit is ten minutes.
- Only sequenced sounds are ripped. Use tools such as vgmstream for BFSTM streams. Wave sounds aren't ripped. Sequences whose data is in a group file that can't be found are skipped. The Wind Waker HD plays some of its music from streams. Its rip holds the music that it plays as sequences. It also holds the game's sound effects. JAudio plays those as sequences too. Four of the game's effects make no sound in a rip with any value. `csfrip` skips them.
- A JAudio game's rip runs the game's mixer on the emulated CPU. It renders far more slowly than other rips. A slow computer may not play it in real time.
- A seek back past the audio that the component or the XMPlay plugin keeps renders from the start of the track. Such seeks happen only in tracks longer than ten minutes and in endless playback.
- Encrypted games (disc images and installable titles) aren't read.
