In CSF 1.6.0, rips contain the variants of sounds that wait for a value from the game, and the states in which games play some pieces of music. Mario Party 10 gets a driver profile. The format moves to version 3. CSF 1.5.0 and earlier players refuse some of the new rips.

CSF rips Nintendo Wii U sequenced music into a PSF-family format. It plays the music with the sound code of the game, or a model of that code, and with a model of how the console mixes sound. The release includes a ripper (`csfrip`), a renderer (`csfplay`), a foobar2000 component and an XMPlay plugin. `docs/csf.md` describes the format.

## New in 1.6.0

- **Effects that wait for variables of the game.** Some sound effects of games on the NintendoWare sound library read a variable that the game sets when it starts them, such as the speed of a lift or the surface under a footstep. Without the value, such an effect played nothing. `csfrip` skipped it. Six games now have a variable profile: Animal Crossing: amiibo Festival, Mario Party 10, Nintendo Land, Super Mario 3D World, New Super Mario Bros. U (all USA) and Wii Party U (USA, Rev 1). A rip of one of them contains a variant of each such effect for each set of values in the profile, such as `SQ_SE_MG0206_JUMP 15=1`. Where a reading of the code of the game found the values, the profile contains them. Otherwise it contains the values that the sequence tests the variable against. `SEQ_BGM_NPG006_THEMA` in Wii Party U is music of this kind. Its variants add a layer at each level of the score. The last one plays the ending. Game-mode rips of amiibo Festival contain the variants too.
- **Variables in `csf_var`.** The `csf_var` tag now also sets the variables of a sequence on the NintendoWare sound library: 0 to 15 for the variables of the sequence and 16 to 31 for the global ones. `T:N=V` sets variable N, 32 to 47, of track T. The players set the variables after the sound starts and before its first tick. A game does the same. In game mode, the player writes them through the code of the game.
- **Track volumes.** The code of a game can set the volume of each track of a sequence as it starts the sound. The stage select of Kirby and the Rainbow Curse plays one piece, `BGM_SEQ_MENU_INTERACTIVE`, with one to three of its tracks. The game picks them by the view: the area view, the stage list of a world, or the boss stage of a world. A rip now contains a file for each of the 15 states, such as `BGM_SEQ_MENU_INTERACTIVE world 3 boss`. The piece played every track at once before. The `.minicsf` of each state contains an archive descriptor with the track volumes of the state. `docs/csf.md` describes it under "Track volumes".
- **A driver profile for Mario Party 10.** Game mode can now run the sound code of Mario Party 10. Game mode plays no effects, and most sequences of the game send to its reverb. Mario Party 10 therefore rips in archive mode unless `--mode game` selects game mode. Archive-mode rips of the game use its 78 voices.
- **More effect profiles.** Archive mode now plays the reverb of Wii Party U on aux A of the TV output. It also plays the reverb of Nintendo Land in each attraction and the delay of the plaza. Nintendo Land defines that reverb and that delay in its code. Archive mode plays models of the two.
- **Music of The Wind Waker HD.** Game mode now starts the music through the starter functions of the game, the way the game starts it. The sound layer mutes some tracks of 14 pieces as it starts them. The state of the game picks the tracks, such as the sail of the boat or an enemy near Link. A rip starts each piece in the state that the sound layer starts in, with the sail down, Link off the boat, his sword sheathed and no enemy near. It also contains each other arrangement, such as `JA_BGM_SEA_SAILING` or `JA_BGM_KAMI_TOWER_80000125`. While some pieces play, the game writes a status to their port 9, such as the phase of a boss fight. A rip contains such a piece once more for each value that changes what the piece plays, such as `JA_BGM_P_GANON_1 9=2`. The battle music also comes with 1 on port 11. The game sets that value when Link hits an enemy. Values 16 to 19 of `csf_var` set the state of the game.
- **The Stalfos of The Wind Waker HD.** Five effects of the game read port 9, the reverb of the room. A rip now contains six variants of the step of a Stalfos (`JA_SE_ST_WALK`), one for each reverb of the rooms that place a Stalfos, such as `9=40`. The other four make no sound with any value. `csfrip` still skips them.
- **The Wind Waker HD (Japan).** The Japanese release of the game has a driver profile too. Its rips contain the same sounds as those of the USA release.
- **Music of Twilight Princess HD.** As Twilight Princess HD starts five pieces, it mutes some of their tracks. A rip now mutes the same tracks. The day music of Hyrule Field contains two arrangements: `Z2BGM_FIELD_LINK_DAY` plays while Link walks, and `Z2BGM_FIELD_LINK_DAY_riding` while he rides. The scenes and battles of the game set the tracks of 17 pieces later, some of them to volumes between 0 and 1. A rip contains a variant of each such state after its piece, such as `Z2BGM_TOAL_VILLEGE_status1`. The day music of Hyrule Field also follows the code of the field: what Link does, the enemies near him and the time of day. A rip contains each path through the piece, in each arrangement.
- **Smaller JAudio libraries.** The `.csflib` of a JAudio game now contains zeros in place of the wave files that the game didn't read while the ripper played the ripped sounds. Each file keeps its size. The game reads its wave files only before a sound starts. A rip therefore plays as before. A rip made with `--no-length` keeps every file whole.
- **Lengths.** Pieces of The Wind Waker HD whose port variants ran to the 10-minute limit now end with two loops and a fade. A sequence whose counted loops run past the limit now loops for ever in its outermost counted loop, and gets two loops and a fade.
- **Speed.** The emulated Espresso CPU runs faster. Rips of JAudio games run the mixer of the game on that CPU. They render faster as a result. The output is the same.
- **Playback.** The foobar2000 component and the XMPlay plugin now buffer 3 s of audio after the start and after each seek before playback starts. A rip that renders faster than real time on average then plays through its slow passages without gaps.
- **Compatibility.** The format is now version 3. CSF 1.5.0 and earlier players refuse the new game-mode rips of amiibo Festival, Mario Party 10, The Wind Waker HD and Twilight Princess HD, and the stage-select states of Kirby and the Rainbow Curse, with a message. Earlier players ignore the variables in `csf_var`. A variant then plays as the effect did before. Rips made with earlier versions play as before.
- **The libraries.** CSF now builds on xsflib 1.8.0 and ntdlib 3.2.0.

## Features

- **Ripping.** `csfrip` rips a Wii U game or a sound archive (`.bfsar`) into a `.csflib` and a `.minicsf` for each sequence. A game can be a Wii U archive (`.wua`) or an extracted title. `csfrip` requires the files of the game to be stored decrypted. Both forms store them that way. The Title Manager in Cemu converts disc images (WUD and WUX) and installable titles to `.wua` files. `csfrip` finds the group files that a game keeps outside its sound archive. It also looks for them in SARC archives. The ripper plays each sound to work out its length and fade tags. It skips the sounds that make no sound. A rip of The Wind Waker HD contains the sound effects of the game too. An effect that reads a value from the game gets a variant for each value. A piece of music that the game plays in several states gets a file for each state. `--bgm` rips only the music. `csfrip` also supports drag and drop.
- **Two rip modes.** Game mode runs the sound code of the game on an emulated Espresso CPU. The rips play as they do in the game. Game mode requires a driver profile for the game. Four games have one: Animal Crossing: amiibo Festival (USA) and Mario Party 10 (USA), on the NintendoWare sound library, The Legend of Zelda: Twilight Princess HD (USA), on JAudio2, and The Legend of Zelda: The Wind Waker HD (USA and Japan), on JAudio1. Mario Party 10 is ripped in archive mode unless `--mode game` selects game mode. Archive mode plays a sound archive from any game with a model of the sound library in the SDK. The model follows the version of the library in amiibo Festival.
- **Mixing.** The Wii U mixes its voices on a DSP. The DSP program comes with the system, not with the game. The sound library of the system then mixes the result for each output. In both modes, CSF does both stages in code: the resampling, filters, envelopes and volumes of the voices, and the final mix stage with its upsampling to 48 kHz. The code does the same arithmetic as the DSP program. A JAudio game mixes its voices on the CPU instead. The player runs the mixer of the game before the final mix stage.
- **Effects.** For a game with an effect profile, archive mode plays the reverb, chorus and delay that the game sets up. Four games have one: Animal Crossing: amiibo Festival, Mario Party 10, Nintendo Land (all USA) and Wii Party U (USA, Rev 1).
- **Rendering.** `csfplay` renders rips to WAV or FLAC at 48,000 Hz, the output rate of the Wii U.
- **foobar2000.** The component plays `.minicsf` files using their length and fade tags. Tag editing, ReplayGain and endless playback are supported. A separate thread renders ahead of playback and keeps up to ten minutes of audio. That makes seeking within a track quick.
- **XMPlay.** The plugin plays `.minicsf` files using their length and fade tags. Endless playback is supported. Like the component, the plugin renders ahead of playback and keeps up to ten minutes of audio.

## Known limitations

- Game mode has profiles for four games. Other games with the NintendoWare sound library rip in archive mode. The model in archive mode follows the version of the sound library in amiibo Festival. A game with another version may play differently from the console. A JAudio game without a profile can't be ripped.
- The DSP program reads the coefficients of its resampling filters from the ROM of the DSP. No file contains that ROM. CSF uses the coefficients of the Wii. They're very likely the same.
- The code of a game can set up the effects of the sound library in the console (reverb, chorus and delay). Archive mode plays them only for a game with an effect profile. Four games have one. Game mode plays without effects.
- The output is the stereo mix for the TV. The GamePad output, the speakers of the Wii Remotes and the surround mix aren't played.
- A sound that depends on values the game sets plays as it does before the game sets any, unless a profile gives it variants. A variant plays its state from the start. The game moves a piece of music into a new state over up to a few seconds. In Twilight Princess HD, the code of some fights writes statuses once the piece plays. A rip leaves those states out. A sequence that draws random numbers takes the same path every time.
- Sounds that play until the game stops them (such as ambiences) get two loops and a fade if the ripper can detect their loops. Otherwise, they play until their notes end. The limit is ten minutes.
- Only sequenced sounds are ripped. Use tools such as vgmstream for BFSTM streams. Wave sounds aren't ripped. Sequences whose data is in a group file that can't be found are skipped. The Wind Waker HD plays some of its music from streams. A rip of the game contains the music that the game plays as sequences. It also contains the sound effects of the game. JAudio plays those as sequences too. Four effects of the game make no sound in a rip with any value. `csfrip` skips them.
- A rip of a JAudio game runs the mixer of the game on the emulated CPU. It renders far more slowly than other rips. A slow computer may not play it in real time.
- A seek back past the audio that the component or the XMPlay plugin keeps renders from the start of the track. Such seeks happen only in tracks longer than ten minutes and in endless playback.
- Encrypted games (disc images and installable titles) aren't read.
