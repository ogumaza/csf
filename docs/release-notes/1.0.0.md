CSF 1.0.0 is the first release of CSF. CSF rips Nintendo Wii U sequenced music into a PSF-family format. It plays the music with the sound code of the game, or a model of that code, and with a model of how the console mixes sound. The release includes a ripper (`csfrip`), a renderer (`csfplay`) and a foobar2000 component. `docs/csf.md` describes the format.

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. For other systems, see the README for instructions on building from source.

## Features

- **Ripping.** `csfrip` rips a Wii U game or a sound archive (`.bfsar`) into a `.csflib` and a `.minicsf` for each sequence. A game can be a Wii U archive (`.wua`) or an extracted title. `csfrip` requires the files of the game to be stored decrypted. Both forms store them that way. The Title Manager in Cemu converts disc images (WUD and WUX) and installable titles to `.wua` files. `csfrip` finds the group files that a game keeps outside its sound archive. The ripper plays each sound to work out its length and fade tags. It skips the sequences that make no sound. `--bgm` rips only the music. `csfrip` also supports drag and drop.
- **Two rip modes.** Game mode runs the sound code of the game on an emulated Espresso CPU. The rips play as they do in the game. Game mode requires a driver profile for the game. Animal Crossing: amiibo Festival (USA) has one. Archive mode plays a sound archive from any game with a model of the sound library in the SDK. The model follows the version of the library in amiibo Festival.
- **Mixing.** The Wii U mixes its voices on a DSP. The DSP program comes with the system, not with the game. The sound library of the system then mixes the result for each output. In both modes, CSF does both stages in code: the resampling, filters, envelopes and volumes of the voices, and the final mix stage with its upsampling to 48 kHz. The code does the same arithmetic as the DSP program.
- **Rendering.** `csfplay` renders rips to WAV or FLAC at 48,000 Hz, the output rate of the Wii U.
- **foobar2000.** The component plays `.minicsf` files using their length and fade tags. Tag editing, ReplayGain and endless playback are supported. A separate thread renders ahead of playback and keeps up to ten minutes of audio. That makes seeking within a track quick.

## Known limitations

- Game mode only has a profile for Animal Crossing: amiibo Festival (USA). Other games rip in archive mode. The model in archive mode follows the version of the sound library in amiibo Festival. A game with another version may play differently from the console.
- The DSP program reads the coefficients of its resampling filters from the ROM of the DSP. No file contains that ROM. CSF uses the coefficients of the Wii. They're very likely the same.
- A game sets up effects (reverb, chorus and delay) in its code. CSF doesn't play them.
- The output is the stereo mix for the TV. The GamePad output, the speakers of the Wii Remotes and the surround mix aren't played.
- A sequence that depends on values the game sets plays as it does before the game sets any. A sequence that draws random numbers takes the same path every time.
- Sounds that play until the game stops them (such as ambiences) get two loops and a fade if the ripper can detect their loops. Otherwise, they play until their notes end. The limit is ten minutes.
- Only sequences are ripped. Use tools such as vgmstream for BFSTM streams. Wave sounds aren't ripped. Sequences whose data is in a group file that can't be found are skipped.
- A seek back past the audio the component keeps renders from the start of the track. Such seeks happen only in tracks longer than ten minutes and in endless playback.
- Encrypted games (disc images and installable titles) aren't read.
